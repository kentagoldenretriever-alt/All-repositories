# サムネ制作の手順（このファイルが唯一の手順書）

PKG＝このファイルの1つ上のフォルダ。最初に次を読む（読み終えるまで手を動かさない）：
1. `PKG/config.json`（無ければ止めて「先にセットアップが要る」と伝える）
2. `PKG/knowledge/採点基準.md`
3. `PKG/knowledge/thumbnail_copy_formula.md`
4. `PKG/knowledge/サムネのルール集.md`

Python は `config.json` の `python`（Mac＝`/usr/bin/python3`／Windows＝`python`）。以下 `<python>` と書く。スクリプトは `PKG/scripts/` にあり、すべて `<python> scripts/…` で実行する。中間ファイルは `config.work_dir/<NO>/`（Driveに置かない）。

## ★完走ルール
- **ゴール＝対象を全件、合格か収束まで採点して納品し、完了日を書くこと。** 途中で止めない。
- **バックグラウンドの結果待ちで会話を終えない。** 待つ間は、次にできる別の作業（記録・次の準備）を進める。
- **採点パネルが走っている間は、候補ファイルと `_eval.md` を書き換えない。**
- どうしても未達で終わるときは、最後に必ず3行残す＝(a)どこまで進んだか (b)何が未達か (c)次に何をすればよいか。

## 手順0 対象を出す
`<python> scripts/find_targets.py --limit <config.schedule.max_cases_per_run>`
- 0件なら「対象なし」と報告して終わる。条件を緩めて拾いに行かない。
- 人が「NO○○のサムネ作って」と名指ししたときは、その案件だけ（範囲外でも可）。
- **1件ずつ完結させる**（作る→採点→納品→完了日）。まとめて作って最後に一括納品しない。
- 案件フォルダが見つからない・元ネタURLが無い案件は飛ばして、理由を報告に書く。

## 手順1 材料を集める
1. 自社の実績が1週間より古ければ更新：`scripts/own_channel.py`
2. `scripts/fetch_refs.py <NO> --url <元ネタURL> --q "<題名の核の語を2〜4語>" --q "…" --q "…" --must 反応`
   - 検索語は指定タイトルと元ネタの題名から、題材の核（国籍・職業・場所・対象）を組み合わせて3通り
3. **元ネタのサムネ（`src.jpg`）と一覧（`ref_sheet.jpg`）を実物で開いて見る。** 1枚見ただけは確認したことにならない。
   - 元ネタが**自社（同じ運営）**なら忠実再現はしない＝勝ち要素を残して器（国・場所・人物層）を替える
   - 元ネタが**他社**なら、元ネタの構図に寄せてよい
   - 同題材の他社は**拡散率（再生÷登録）3以上**だけを参考にする。登録が数百の突出は広告の可能性があるので、2本以上に共通する要素だけ採る

## 手順2 言語化シートを書く（生成の前・必須）
`work_dir/<NO>/_元ネタ言語化.md` に、次の見出しで書く（ルール集2章）：
- **A 文字**：元ネタ3行の実物と役割 → **移植表**（今回の各行の語をどこから採ったか1語ずつ。自分の言い換えは入れない）
- **B 中央画像**：元ネタの絵が何をしているかを構造で箇条書き → **器替え表**（元ネタ／今回）
- **C 記号・小セリフ**：実物の個数・位置・中身 → 今回の指定
- **E カスタマージャーニー**：(あ)どこで出会ったか (い)最初に目に入る所 (う)次に視線が動く所 (え)知りたくなった空白 (お)押した瞬間の期待 (か)本編で回収されるか
- **D 照合リスト**：合成後に1項目ずつ潰すチェック（顔の感情が1行目と一致／目の線が可視帯の上端＝`template.band[0]`より下／元ネタと並べて器が替わって見えるか／3行目の最後の語／造語ゼロ 等）

## 手順3 3行を決める
- 寄せる順＝**①元ネタのサムネの実物 ②指定タイトル**。他社・自社のサムネの実物からも採る。**どこにも無い言葉を自分で考えない。**
- 型は `thumbnail_copy_formula.md` と採点基準G5。**字数はこのチャンネルのテンプレの実測値＝`config.json` の `template.chars`**（`l1_max`＝1行目の括弧込み上限／`l2`＝2行目の目安／`l3`＝3行目の目安／`l3_max`＝3行目の上限。同梱テンプレなら 18／20〜22／13〜14／14）。3行目の最後の語は高温語か「理由／とは／末路」。
- 3行を続けて音読し、誰が・どこで・何が起きたかが繋がるか確かめる。
- **文字だけ先に合成して潰れないか見る**（中央画像は仮のもので可）：
  ```python
  import sys; sys.path.insert(0, "<PKG>/scripts"); import thumb_psd_compose as T
  T.render(out="<work_dir>/<NO>/texttest.png", psd_out="", l1=..., l2=..., l3=..., img="<仮の画像>")
  ```
  書き出した画像の上端・下端を切り出して開き、字が重なっていないか見る。

## 手順4 中央画像を2〜3通り生成する（codex・必ず1枚ずつ直列）
- 構図が本当に違う候補を2〜3通り（同じ発想を並べない）。元ネタの構図を写すのが基本。
- 実行：プロンプトを `<work_dir>/<NO>/prompt_A.txt` に書き、
  `<python> scripts/gen_image.py <NO> A --prompt-file <work_dir>/<NO>/prompt_A.txt`
  → 生成された画像を `~/.codex/generated_images/` のサブフォルダから拾って `<work_dir>/<NO>/cand_A.png` に置く（Mac/Windows共通）。
  2〜5分かかるのでバックグラウンドで実行し、終わったら次の候補の生成を始める（**同時に2本走らせない**）。
  画像が出なかった／時間切れのときは、ログ（`run_A.log`）を見て語を言い換えて再実行する（入浴・子ども等の語や否定形の指示で止まることがある）。
- プロンプトは英語で、次の見出しで書く（ルール集4章）：
  `[Purpose]`（日本のYouTubeサムネの中央画像・上20%と下32%に文字が乗る）／`[Size] 16:9 landscape, 1792x1024`／
  `[Style] candid documentary-style photograph, like a single frame cut from a TV documentary, shot on a real camera, natural available lighting, realistic skin texture with pores and slight imperfections, natural asymmetry, authentic and unposed, photojournalistic. Bright, vivid natural colors`／
  `[Scene]`／`[Subjects]`（**位置と大きさを%で指定**：x範囲、目の高さ＝画像高さの34〜36%、顔の高さ＝20〜26%）／
  `Everything that matters lives between 20% and 64% of the height.`／
  `[Avoid] AI-generated look, 3D render, CGI, plastic or waxy skin, over-smoothed skin, over-saturated HDR glow, perfect symmetry, malformed hands, extra fingers, uncanny face, illustration, cartoon, exaggerated theatrical grimace, over-acting, empty margins or letterbox bars. No text, no letters, no flags, no symbols, no arrows, no numbers, no watermarks, no overlays, no readable signs or logos.`
- ★顔の感情は**1行目と一致させる**（結末の感情は顔で見せない）。表情は自然に、形ははっきり。
- ★人種・属性を否定形で書かない（生成が止まることがある）。肯定形で書く。
- ★明らかな破綻（指・顔の崩れ・題材違い）だけは生成段階で捨ててよい。それ以外は全部合成してから比べる。

## 手順5 合成する（候補ごと）
1. `scripts/grid.py <候補の画像>` → **グリッド画像を開いて座標を測る**（顔の範囲・目の高さ・視線の向き・指す対象）。
2. `bg_dy` を決める＝1行目の帯の下端（`template.band[0]`。同梱テンプレはy150付近）が**額の上3分の1より下に来ない**よう背景を下げる（目がその線より下）。頭が切れるのは可。顎は `template.band[1]`（2行目の帯の上端）に沈めない。
3. **記号ゲートを通す**（合成の前に必ず）：
   ```python
   import thumb_marks_guard as G
   G.guard(no="<NO><候補>", ch="main", face=(x1,y1,x2,y2), gaze="left|right|up|down|camera",
           target=(…) , mq=(x,y,大きさ,大きさ,角度), ar=(x,y,大きさ,大きさ,回転), flag=(x,y,幅))
   ```
   - `!?`＝驚いている人物の**頭のすぐ横**（顔から200px以内・顔に重ねない）。`!!`は mark="!!" で差し替え
   - 矢印＝**視線の先**の対象を**外から**指す（対象に被せない）。人物がカメラ目線なら矢印は置かない
   - 記号が2人に分かれるときは、人物ごとに guard を2回通す（2つ目の記号は `mq2`＝guard対象外なので目で確認）
   - 国旗は理由があるときだけ（元ネタにある・国籍が主題）。`assets/flags/` の画像を使う
   - `config.json` の `template` で空（`"layer": ""`）になっている記号は、このチャンネルのテンプレに無い＝使わない
   - × で止まったら座標を直す。△ は読んで判断する
4. 合成：`T.render(out=…/<NO><候補>.png, psd_out=…/<NO><候補>.psd, l1,l2,l3, img=<候補の画像>, bg_dy=…, mark="!?", mq=…, ar=…, …)`（1枚2〜4分・Photoshopが開いている必要あり）。終わったら `_run.jsx` を消す。
5. `G.verify(<png>, mq=…, ar=…, eyes=(x,y))` → 拡大の検品画像を**必ず開く**。
6. `scripts/color_check.py <png>`（参考値。自社上位のレンジと比べる）。
7. **完成品を開いて目で見る5点**：①目の線と1行目 ②顔が2行目の帯に沈んでいないか ③記号が誰のものか一目で分かるか ④3行目の字が潰れていないか ⑤言語化シートのD照合リストを全部。

## 手順6 採点する（3組・並列）
1. `scripts/small_sheet.py --out <work_dir>/<NO>/small_sheet_r<周>.jpg <候補…> <元ネタ> <他社2本> <自社上位4本>`
2. `work_dir/<NO>/panel_brief.md` を書く（案件・3行・元ネタの型・見るファイルの絶対パス・色の実測値と自社レンジ）。
3. Agent ツールで3組を**同時に**起動する（G2はモデル指定なし、G1・G5は `model: "sonnet"`、`run_in_background: true`）。各プロンプトに入れるもの：
   - 組の名前と役割／`panel_brief.md` と `採点基準.md` の自分の組の節を読むこと
   - 候補の絶対パスと各候補の説明／元ネタ・一覧のパス／「第○周・前の周と同じ基準で」
   - 「関連動画欄で元ネタと自作が隣に並んだら、どっちを押すか」を先に1行で言い切ること
   - 各指摘に【設計由来】【実装由来】と、`_eval.md` の既出なら「既出#番号」・新しければ「新規」を付けること／ファイルを書き換えないこと
   - 末尾に採点基準の「返答の形式」の枠をそのまま貼る
4. 3組そろったら加重平均（G1 24%・G2 48%・G5 28%）を出し、`_eval.md` に記録：各組の点・加重平均の推移・指摘を**新規／既出に分けて番号付きで全部**・両論・次の周の方針。
   - パネルの指摘が実物と違う（事実誤認）なら、確かめてから「除外」と書く。

## 手順7 直して回す
- 直し先の切り分け：**画像が原因→再生成／3行・記号が原因→合成のやり直し**。
- 最低点の次元から直す。**直した箇所には新しい傷が出る**ので、直したら必ず開いて見る。
- 2周目以降は90未満の組だけ走らせる。引き継ぎ込みで90を超えたら3組全員で確認。
- **点が下がったら最高点の版に戻す。** 加重平均が2周続けて+1.0未満しか動かなければ、直し方を変える（局所の置換だけで回し直す）。
- 終わるのは【合格＝90以上】【収束＝直近2周の指摘がすべて既出】のどちらか（`scoring.max_rounds` があればその周数で最高点の版）。終えるとき `_eval.md` に：推移・終了理由・いちばん低い次元が設計由来か実装由来か・両論。
- 人が「この版で納品して」と言ったら、その版で終える（`_eval.md` に「人の判断で納品・90未達」と書く）。

## 手順8 納品と完了日
1. `scripts/deliver.py <NO> <採用PNG> <採用PSD> --hint "<指定タイトルの一部>" --records <_eval.md> <_元ネタ言語化.md>`
   → 案件フォルダの中に3点・`サムネ/`に記録2つ・md5一致・直下に取り残しなし、を表示で確認。
2. `scripts/write_done.py <NO>`（完了日＝今日）。**`--check` は人が「チェック入れて」と言った時だけ。** 読み返しの表示で行・セル・値を確認。
3. 次の案件へ。

## 手順9 レポートと報告
- その日に処理した分を1つのHTMLにまとめる（完成サムネと元ネタを並べる／3行と語の出どころ／言語化の要点／色の実測／各周の点／文言の変遷／246×138の一覧／判断してほしい点）。画像はJPEG（960×540・品質82）にして data URI で埋め込む。
  - Artifact ツールが使えれば公開してURLを出す。使えなければ `work_dir/_レポート/<日付>.html` に保存してパスを出す。
- 報告（チャット）：処理した全案件について、3行・点数（加重平均と各組）・終了理由・納品先・シート記入の結果・残った課題。最後に**残件のNOと理由**。90未達なら点数と「90未達」を必ず書く。
